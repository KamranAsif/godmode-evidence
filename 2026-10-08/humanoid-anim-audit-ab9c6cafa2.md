# BattleDuty third-person humanoid animation audit

Audited 2026-10-07 against origin/main `a1d5542d9` in an isolated worktree. Scope: 14 production enemy bodies, ten stream-sniper operator bodies from #1101, Assault/Breach/Marksman and the retained Daemon strike donor. First-person Infima arms and viewmodel poses are excluded.

## What actually exists and runs

GLB inventory: all ten operators contain 117 named clips; ordinary enemies contain 117, with additional grenade/radio/slam/strike clips on specialists. Player bodies have 118; Daemon has 121. **None of these 28 GLBs contains diagonal locomotion, turns, directional hit clips, cover, lean or vault semantics.** These counts include weapon aliases, not 117 independently captured motions. `compile-mixamo-catalog.mjs` aliases rifle motion for MachineGun, Shotgun and SniperRifle, and builds pistol crouch/strafe from rifle legs and a sampled native pistol arm pose. It even replaces the imported native pistol strafes.

The archived Breach Pro Rifle Pack already contains eight directions of walk, run, sprint and crouch walk, plus standing/crouched 90-degree turns. Its Shooter Pack has forward/back starts and stops. These files are **not imported by the game manifests**. The pistol pack contains walks, runs, backpedal and arc motions; the selected manifest uses run for walk. Reuse these real Mixamo sources before spending time downloading duplicates. The signed-in Mixamo profile currently shows Kamran; new shared motions should be downloaded on the saved Breach rig.

Runtime is an AnimationPlayer plus a small TypeScript state selector/manual native-track blend, not an authored AnimationTree. `soldier_view.ts` drives production soldiers and stream snipers from `adminInterpolation.renderedMotion`, relative to actual displayed yaw. `admin_directional_gait.ts` blends two cardinal loops and samples only hips/legs for diagonals, with measured stride scaling. This is better than cardinal snapping, but does not use captured diagonal footwork. `game_world.ts` uses a four-sector selector for player world bodies. `third_person_animation.ts` selects full-body reload/jump/shoot and has no diagonal states. Enemy aim is a runtime hand/arm grip solver; rifle shooting while moving already has a native upper-body overlay. Flinch rotates the whole root, and enemies are planted during flinch/windup/recovery. Deaths include six real native clips but selection is not based on incoming impact direction or hit region. Locomotion removes horizontal source root travel; death and mantle retain it. Animation LOD deliberately skips far-body samples.

## Comparison with modern shooter practice

This is a production-practice comparison, not a claim to know proprietary current blend-tree internals. DICE's [Battlefield 4 layered-animation presentation](https://media.gdcvault.com/GDC2014/Presentations/Duffin_Ryan_Animation_Bootcamp_Using.pdf) describes posture/weapon families with layered weapon actions; [Battlefield 3 methodology](https://media.gdcvault.com/gdc2012/slides/1_Visual%20Arts%20Track/Animation%20Methodology%20for%20Battlefield%203.pdf) calls out foot planting, AI turns and real-time blend tuning. CoD's [official Black Ops 6 reveal](https://www.callofduty.com/en/blog/2024/06/call-of-duty-black-ops-6-worldwide-reveal-announcement/) documents multidirectional sprint and connected movement/reactions. Massive's [The Division AI presentation](https://media.gdcvault.com/gdc2016/Presentations/Gillberg_Jonas_AI_Behavior_Editing.pdf) supplies the contextual AI/animation comparison; Ubisoft's [motion matching presentation](https://www.gdcvault.com/play/1023280/Motion-Matching-and-The-Road) illustrates continuity beyond isolated loops. The practical target here is smaller: native eight-direction footwork, coherent posture and weapon layers, readable transitions and speed-matched feet. Motion matching is unnecessary for this prototype.

## Execution boundaries and validation

Worst-first PR sequence: (1) missing native directions and ring wiring; (2) distinct walk/run and posture coverage; (3) starts/stops/turns; (4) upper-body reload/shoot/hit and contextual traversal where the state exists. Keep animation manifests, assets and presentation isolated from stream-sniper class/AI rules in lane %182. No auditor agents or end-to-end suites. Use default cheap development, owned CLI session and named instances, at most four rendered engines machine-wide. Each motion PR gets a <=10 s actual window video. Run format/build/lint, meaningful pure unit checks and a headless smoke, then the full `pnpm test` once per merge candidate. Merge only after that full suite passes, per this task's explicit instruction.

This is a clip/wiring audit. Existing scene structure and motion inventory were inspected; foot-contact quality, clipping and perceived feel require rendered playback and Kamran's in-game review. Exact proprietary per-title eight-way grids are not asserted. No first-person files were changed.
